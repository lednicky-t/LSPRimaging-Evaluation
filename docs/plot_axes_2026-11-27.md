# Plot axes: tick spacing, display range, grid (2026-11-27)

Maintainer's request: a "Plot" group on the Sensorgram's View tab (after Steps), like Origin / Excel's axis options, copied to the LbL and S_bulk windows. Phase 1 (this note) = tick spacing,
display range, grid, session saving, reset; then axis breaks, the x zero and guides (below). **Not built yet**: saved style presets. Plan for those at the end.

The ribbon's first tab is now **Data** (it was "Plot"; renamed so the group can have that name). A saved "Plot" tab matches no tab, so the first tab is shown once.

## Decisions (flag if not meant)

1. **Options belong to the quantity, not the axis.** A step of 50 means nothing once x shows time instead of cubes. Keyed by the axis label ("Cube (#)", "Peak position (nm)"). The S_bulk
   x key leaves the wavelength out ("Refractive index (RIU)"). A reworded label starts automatic again (nothing is lost: the old row stays in the session, unused).
2. **A typed range is exact.** The room the plan bar and step table add above / below the data is not added to a pinned end, so the bar overlays the data there. Setting a range also ends the
   user's own zoom; "A" / View All return to the range. One end may be left empty (stays automatic).
3. **Tick guard.** A step that would draw more than 400 ticks across the *visible* range is ignored (pyqtgraph would stall); it is checked again on every zoom. A too-fine minor step alone is
   left out. The typed value stays.
4. **LbL**: its one-tick-per-cycle labels (`setTicks`) win over a spacing in pyqtgraph, so they are left out while a major step is set and come back when it is cleared.
5. **Clearing the major step clears the minor one** (its field is greyed out without a major step).
6. **Not undoable** (like the line order). Reset is the way back.
7. S_bulk / LbL apply a changed option by redrawing the plot (~100 ms); the Sensorgram only re-ranges.

## Facts about pyqtgraph 0.14 used here

- `AxisItem.setTickSpacing(major, minor)` needs both; the styler passes `levels=[...]` so a major step alone works.
- The grid is drawn at every tick level, the minor level at half strength; its strength also fades with tick density (`generateDrawSpecs`), so "15 %" is a ceiling, not an exact alpha.
- `ViewBox.autoRange()` switches the auto-range of **both** axes off (`setRange` default). The windows give it back with `release_unpinned()` at the start of the next redraw.

### Rules

1. **Drawn x vs data x.** The data never change; items are placed at `forward(x)`. A break is `[start, end]` in data units; the gap is a fixed 1.2 % of the length kept (not of what was removed).
   `inverse(forward(x)) == x` everywhere, also inside a break (the gap is the removed stretch squeezed in proportion), so a click or a step edge in the gap still means a place in the data.
2. **Points inside a break are not drawn** (the two ends are); every per-point array of a line loses the same points (y, band, baseline curve, out-of-date flags, mask marks). **The line runs across
   the gap** from the last point before to the first after (Origin's way), unless the Plot menu's **Lines** row says **Break** (rule 8). A cube inside a break has no place on the axis: the cube cursor is hidden there.
3. **Ticks and labels**: **one spacing for the whole axis**, chosen by pyqtgraph as for a continuous axis of the data that are kept (their length, the pixels they have), then laid into every stretch on multiples of it (from the zero) and drawn at their drawn place, labelled with the data value. A break therefore never changes the tick density (2026-11-27: choosing a spacing per stretch gave a 170 px stretch of 0-40 a 1-unit minor level, 32 minor ticks, and labels running into each other, while the wide stretch had 2-unit ones). A tick step of the Plot menu holds in every stretch.
   A tick exactly at a break's end is drawn at both sides of the gap.
4. **The break mark is the handle** (changed 2026-11-27: the blue slider box is gone). `BreakHandle` is an invisible grab area over the gap and its `//` (pointer: horizontal arrows, at least 16 px
   wide); under the pointer the marks show in the accent colour, and while it is dragged a dashed line goes up through the plot at the new place. A drag moves only that ghost; the data are laid out
   again on release (a redraw per mouse move would cost ~0.8 s with 160 lines). The distance dragged is the same in drawn and data units (the gap and the length kept do not change), and stops just short of a neighbour or of the data's end.
5. **Edit mode** (pencil in the Plot menu): the axis is continuous again with each break a shaded span; click adds one (5 % of the data's length), drag an edge or the body edits, right-click removes.
   The plan bar's gestures wait, as in the anchor edit; the two edit modes refuse each other (the anchor edit ends the break edit; the break edit is refused while the anchor edit runs, with the reason in the note).
6. **Show group switch** (`sensorgram/view_breaks`, remembered like the other toggles): off = continuous, uncompressed axis; the breaks are kept. Greyed while there are none.
7. **A pinned x range of the Plot menu is in data units** and is converted for the view.
8. **Lines: Continue / Break** (`AxisOptions.join_lines`, saved as `"join": false` only when Break; per x quantity; a row under the break row of the Plot menu). With Break a line, its baseline
   curve and its band end at the last point before a break and start again at the first after it (a break between two points, with none inside, cuts too); a smoothed line is smoothed piece by
   piece. Done by a NaN after the last point before the break (`connect="finite"`) and by splitting the band's runs (`_with_gaps`, `_smooth_pieces`, `_split_runs`, `_cuts_after` in `plot.py`).
   Changing the option redraws the lines only: the layout, the view and the zoom stay.
9. **Figures**: the `//` marks are part of the axis layer; the handles and spans paint nothing while pyqtgraph exports (`_exportOpts`). SVG labels checked: 0, 10, 20, 30, 60, 70, 80, 90 for a break (30, 60) with a step of 10.

### Not seen by eye / things to check
The look of the gap marks and the handle (size, colour on the light themes); dragging a handle and an edit span with the real mouse; how a step spanning a break looks on the bar (it gets shorter); a step
that lies entirely inside a break becomes a sliver inside the gap (left as is: say if it should be hidden); the stats table cells of a step that spans a break.

## X offset / time zero (built the same day)

Sensorgram x axis only. `AxisOptions.zero` (data units, per x quantity, in the `plot_axes` block as `"zero"`; the schema stays 1.17, it is an optional key). The "Zero at" row of the Plot menu:
a typed value, or "Step..." (a list of the plan bar's steps, asked each time it opens; picking one copies that step's start into the field, so the session keeps a number, not a link).

Rules:
1. **Only the printed numbers change.** `BrokenAxisItem.set_zero`: pyqtgraph's ticks are computed in the shifted numbers and put back at their data place, so ticks stand on multiples of the step
   *from the zero* (also with an automatic step) and the label is `data - zero` (rounded to 9 decimals so noise prints as 60, not 59.99999999, and -0.0 as 0). Data, cursor, plan bar, step
   table, stats and everything the plot reports stay in the data's own x.
2. **A typed x range is in the printed numbers** (`AxisStyler.pin_ranges` adds the zero back; "Use view" subtracts it). Axis **breaks stay in data units** (their handles move them).
3. Changing the zero while a range is typed moves the data window with it (the range is in printed numbers). Say if the range should stay in data units instead.
4. The window plots (LbL, S_bulk) have no zero row; a zero saved for them (it cannot be) would be kept untouched.
5. **Not done on purpose**: the axis label does not say "from zero" (the quantity key of the saved options is the label); the hover texts of the plan bar still show the data's own times.

Tests: `tests/integration/test_lspri_plot_zero.py` (18).

## Guides (built the same day)

Horizontal reference lines at a y value, in all three plots (Sensorgram, LbL, S_bulk). A second button in the **Plot** group ("Guides", icon drawn in code in `axis_break_icons.py`).

| Piece | File |
|---|---|
| `Guide(value, label, color, style)`, `MAX_GUIDES` = 6, `normalized` | `domain/guide_lines.py` |
| Saved: `AxisOptions.guides` of the **y side** (so per plot and per y quantity), key `"guides"` in the `plot_axes` block (schema stays 1.17) | `domain/plot_axes.py` |
| The table (pop-up) and every way to change a guide: 8 fixed rows (value, label, dashed / solid / dotted, colour, show y), Clear all, note; `add_guides`, `move_guide`, `remove_guide`, `change_guide`, the guide's own menu | `panels/sensorgram/guide_controls.py` |
| Drawing and dragging: one `GuideLine` (a movable `pg.InfiniteLine`) per guide, label at the right end, open / closed hand, `index_at`, `moved` | `panels/sensorgram/guide_items.py` (`GuideLines`) |
| Figure: layer **"Guides"** (one named part per guide: value + label), in `svg_layers.SECTIONS` after "Regions" | `export_parts()` of the Sensorgram plot; the windows' export draws the plot item |

Rules:
1. **A fixed number of rows, `MAX_GUIDES` = 8** (not a growing list): a pop-up (`QMenu` with a widget action) does not reliably resize while open, and the panel must not jump. Empty the value field to remove a guide; rows left empty in the middle close up on the next refresh.
2. **Behind the data, never in the autoscale** (`ignoreBounds`, z = -8: above the bands, below the baseline window and every trace). A guide far from the data does not stretch the view.
3. **A guide edit changes nothing else**: `PlotAxes.only_guides_differ` lets the Sensorgram skip the autoscale (the user's zoom stays) and the windows skip the redraw (the lines are put right at once). The windows draw their guides again at the end of every redraw (`PlotItem.clear()` takes them out).
4. **Reset (Plot menu) keeps the guides**; "Clear all" in the Guides panel removes them. (Breaks and the zero are cleared by Reset.)
5. Colour list is fixed (Auto = the theme's muted text colour, so it stays legible on every theme); a colour from a session file that is not in the list shows as "Custom" and is kept.
6. A label's braces are escaped (pyqtgraph formats an infinite line's label).
7. A guide's value is a y value in the axis' unit; the y axis has no zero offset, so there is nothing to convert.

Tests: `tests/integration/test_lspri_plot_guides.py` (20) and one in `test_lspri_sensorgram_view_tab.py`; the second round of breaks (Lines option, drag ghost, speed-ups) in `tests/integration/test_lspri_break_lines_and_speed.py` (18). A typed tick step used to lose the guides (the controls rebuilt the options without them): fixed and pinned there. Unseen by eye: the label's position and legibility, the pop-up's width with six rows, dash look in a figure.


### Guides made and changed on the plot (second round, 2026-11-28)

Maintainer's request: add guides with a right-click, from a selected step, move them by hovering and dragging, a menu on the guide; the pop-up keeps a table of them.

| Gesture | What happens | Where |
|---|---|---|

| Select a step (or several) on the plan bar, right-click > **Add guide from step** | one guide per step at **the mean of the plotted lines' means** in the step (the step table's numbers, as drawn), labelled with the step, showing its value; a step no line has a number for gives none; the entry is left out while there is no step table | `plot.py` `step_guides`, `plan_actions.py` `build_menu` |
| Hover a guide, drag with the left button | open hand over it, closed while held; the label (with "show y value") follows live; the new value (rounded as above) is reported once on release (`moved`, queued) and saved | `guide_items.py` `GuideLine` |
| Right-click on a guide (within 5 px) | its menu: **Rename...**, **Colour...**, Default colour (only with a colour of its own), **Show y value** (check), **Remove guide** | `guide_controls.py` `build_menu`; `_MiddlePanViewBox.guide_right_click` takes it before the plan bar and the view's menu |

Rules:
1. **One place changes guides**: the table's object (`GuideControls`), which writes the session value; the plot only reports gestures (`guide_add_requested`, `guides_add_requested`, `guide_moved`, `guide_menu_requested`). The three plots redraw through the one `set_axes` path, which is a no-op for the view (rule 3 above).
2. **Full table** (8 guides): a new guide is refused and the note under the table says so (a step menu with several steps adds as many as fit).
3. **Not while an edit mode owns the right button** (anchor points, break spans): no guide menu then (dragging still works).
4. The windows (LbL, S_bulk) have the table and the dragging; they do **not** have "Add guide here" / the guide's right-click menu (their view menu is pyqtgraph's own; say if wanted).
5. "Show y value" prints `{value:.6g}` of the line's own y, so it is the number the guide stands at, not a rounded copy.
6. Menu icons: `guide_add` (plus), `guide_from_step` (ruler-measure), `show_value` (eye) in `menu_icons.ICONS`; the rest reuse `rename`, `colour`, `colour_clear`, `delete`.

## Speed of the Plot menu and of the breaks (2026-11-27)

Measured with 160 lines x 3000 points, offscreen (`scratchpad` bench, not kept): a repaint of that plot is ~300-400 ms by itself (the lines, the bands, the grid), whatever the option.

| Action | before | after |
|---|---|---|
| Add / move a break, switch breaks on or off, switch Lines (call, without repaint) | 650-730 ms | 300-420 ms |
| Tick step, minor step, grid (call, without repaint) | 16 ms and the user's zoom was ended | ~0 ms, zoom kept |
| `_through_breaks` (which points stay, where they are drawn) | ~160 ms | ~30 ms |

What was done (1 = why it was slow):
1. A change of the breaks ranged the view **three times** (the redraw, `_relayout`, `set_axes`): now once (`_autoscales` counts them; `set_axes` ranges only when no redraw did).
2. A pooled band edge was still joined to its old fill, so every `setData` made the fill work out its path again (3 times per band): the edges are silenced while data go in, `setCurves` works
   the path out once (~0.2 s).
3. `_through_breaks` worked out the kept points and their drawn x once per line: now once per distinct x (the lines of a plot share one).
4. `_finite_runs` was a Python loop over every point (~100 ms for 160 lines): vectorised, equal output (checked against the loop on random data).
5. A tick step, the minor step, the grid or the grid strength no longer re-range the view or end the user's zoom (`PlotAxes.needs_rerange`); the LbL / S_bulk windows no longer redraw for them
   either (`PlotAxes.needs_redraw`: only a range, or a step set / cleared, does).

What is left is pyqtgraph's: building the path of every line, band edge and fill (~0.2 s) and the repaint itself. Not done: updating the existing items' x in place on a break change instead of
`show_series` (would save the legend rebuild and the pool bookkeeping, ~50 ms; the items' paths still have to be built).
