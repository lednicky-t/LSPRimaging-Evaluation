# Where the rewrite stands: feature-by-feature record (moved out of CLAUDE.md, 2026-10-29)

This is the "Where the rewrite stands" section of `CLAUDE.md`, moved here **verbatim** on 2026-10-29 because it had grown to 25 KB and was loaded into every session. Nothing was reworded. `CLAUDE.md` now keeps one line per feature plus the rules that are inside these paragraphs (extracted, with the same wording where possible). When the two disagree, the rule in `CLAUDE.md` wins; when you need the reasoning, measurements or open points of a feature, search this file by feature name.

Kept current only up to the move. Newer work is recorded in its own dated doc (see `docs/README.md`).

### Where the rewrite stands (bullets are dated per feature, kept current to 2026-10-29; open decisions: `docs/whole_app_audit_2026-10-29.md`)

- **Built, with UI**: Dataset (Workflow panel); Image panel (ribbon tabs View, Image tools, Mask, ROIs, Chromatic, Background, Export (OME-Zarr, moved from the Workflow panel 2026-10-20; "Rotate/crop" exports the processed image as uint16 + `valid_mask`, values rounded onto the camera step: `docs/rotated_zarr_export_interpolation_2026-10-20.md`); ROI overlays, area selection, cursor readout, scale bar); Histogram panel; ROI / Group table; task indicator; sessions with autosave; layout presets; remembered UI state; Edit -> Undo / Redo; Edit -> Preferences (2026-10-19, replaced the Options menu; app-wide settings only, panel settings stay in their panel; scope, what is planned and what is deliberately not exposed: `docs/preferences_dialog_2026-10-19.md`).
- **Session carried with the export (2026-10-22)**: the Export tab's *Session* button (on by default) moves ROIs, masks, chromatic correction and mask pointers into the exported pixels' coordinates (a shift by the frame origin; masks resampled once with the app's own warp; nothing refitted or recalculated) and saves them as a session of the exported dataset; the app then asks whether to open it. Pure part `storage/session_carry.py`, task `storage/session_carry_task.py`; record: `docs/session_carry_export_2026-10-22.md`. The fast libtiff TIFF decoder (`dataset/io.py`, verified against tifffile at run time, `LSPR_TIFF_DECODER=tifffile` switches it off) is now **on for every thread**, not only the render thread (2026-10-22; 1.7x on one thread, 3.8x on four, `docs/export_speed_2026-10-22.md`). The export itself got faster the same day (libtiff decode and a fused rotate-and-round in the workers, byte-identical output) and reports its time and rate in the status bar and in the question box after a carried export: `docs/export_speed_2026-10-22.md`.
- **Parallel work tunes itself (2026-10-22)**: the OME-Zarr export, the transient Scan and analysis step 1 (`analysis/scan.py`) take their worker count from `lspr_core.perf` (`get_runtime().begin(...)`), the default is **Standard** (every core but one, no searching); Edit -> Preferences can switch on **Tune automatically** (measures images per second while the job runs, settles on the cheapest count within noise of the best and saves it for this computer, after which Standard uses it; "Forget saved counts" deletes it) or set a **Fixed number**; cores kept free and low priority; all remembered (`storage/ui_state_keys.py` `PERF_*`). Tuning was measured on the dev laptop (flat 3-7 workers): no gain, a few percent cost while searching, so it is opt-in. The saved counts live in `perf_profile.json` beside the app settings (`perf_setup.py`, installed in `main()` only, so tests never touch it). **A tuned job must write/find identical results at any worker count** (hash test: `tests/integration/test_lspri_export_workers.py`); never tune what is saved. A new fan-out follows the recipe in `docs/performance_tuning.md` (repo root). The earlier I/O-fraction tuner (`ADAPTIVE_*`) is gone from `dataset/io.py`; the old generation (`io/dataset.py`) still has it.
- **Mask-tab Scan and Auto mask (2026-10-17)**: *Scan* finds dark, sharp objects that crossed the field (particles, hairs, bubbles) and marks those frames with pink pointers on both Mask rows; `MaskPointersModule` (code name since 2026-10-22; the detector and its `TransientEvent` keep "transient") holds the list (cosmetic, never a mask, saved in the session, schema 1.4). *Auto mask* is the separate step that turns the standing particle pointers into individual masks (contour grown by N px, merged with the mask in effect, one undo step; `mask_auto_task.py`, on a worker thread, also from a pointer's right-click menu). Only what sits on the image border and goes nowhere is an `artefact` (never masked); a particle that arrives and rests is a particle at rest and is masked (plan doc section 12, with its known limit). The PNG group also has *Export all masks* (one named PNG per mask + `masks_index.csv`). Read `docs/auto_transient_scan_and_mask_plan_2026-10-16.md` (sections 9-11), `docs/auto_transient_mask_exploration_2026-10-16.md` and the audit `docs/transient_scan_automask_slider_audit_2026-10-17.md` (lifecycle rules: a scan or an Auto mask run belongs to the dataset, session and mask it started with); command line: `tools/scan_transients.py`.
- **Mask-tab edit preview (2026-10-29, uncommitted, unseen by eye)**: Threshold, Local contrast and Morphology now show the pixels they would select / change as a tint on the image (eye button in each panel, one shared remembered state, only while the Mask tab is open and Play is not running); Morphology previews on hover over a button, a click still applies at once. Threshold / Local contrast **Add / Subtract are wired** (were disabled): the candidate is made on a plain thread (`image_tools/mask_candidates.py`, 0.2-4 s at 1.2 MP) and shared by the preview and the buttons. Pieces and rules: `docs/mask_edit_preview_2026-10-29.md`.
- **Mask-tab Eraser (2026-10-29, uncommitted, unseen by eye)**: seventh entry of the Manual-edit picker. With the Mask tab open and the Eraser picked, a left click on the image removes the 8-connected blob ("grain") of mask pixels under it, at the Persistent / Individual scope, inside an area selection if there is one; cross cursor; the click does not select the ROI under it. `panels/mask_grain_eraser.py` + `CanvasInteraction._click_erase`; 30-45 ms per click on the GUI thread; not on the undo stack (like the other tools' Add). Record: `docs/mask_eraser_2026-10-29.md`.
- **ROI feature detection (2026-10-29, uncommitted)**: `image_tools/mask/roi_features.py` (pure) finds small features on / around ROIs from one frame (radial profile per ROI, then each ROI against the family of all ROIs: median + 3 principal components, second pass, width / edge / area rules); lab `tools/roi_feature_lab.py` writes a table, a mask PNG and an overlay montage. Found all ten ROIs the maintainer named, 94 of 160 ROIs have features. **In the app as the Mask tab's "ROI features" tool** (Manual edit picker; eye, settings popup, Process, Apply): `mask/roi_feature_run.py` (pure job: fits on worker processes whose count comes from `lspr_core.perf`, task key `mask.roi_features`, identical results at any count) + `image_tools/roi_feature_task.py` (`RoiFeatureTask`: thread, progress/Cancel in the status bar, keeps the result and the fit; 7 s for the first run, 1.4 s for a re-run with other numbers) + `RoiFeaturesEditPanel` in `panels/image/mask_edit_panels.py`. The finder looks at the picture, never at the mask; Apply merges at the Persistent / Individual scope through the same editor Threshold uses; the result is dropped when the ROIs, geometry, background or chromatic model change. **Masking the features did not reduce noise or raise SNR of the polynomial-centroid metric on the bulk-step data** (it shifts each ROI's absolute peak by ~100 pm, up to 1.1 nm): `docs/roi_feature_detection_2026-10-29.md`.
